# k0s Update Server - Reference implementation

This repo serves as k0s update server reference implementation. It provides the basic channels descriptions that is expected from an update server.

## Available channels

- `stable`
- `stable/v1.34`
- `stable/v1.35`
- `stable/v1.36`
- `stable/v1.37`
- `latest`
- `unstable`

`stable` points to the newest k0s release without pre-releases. Each
`stable/vMAJOR.MINOR` channel points to the newest patch release of that minor.
`latest` points to the same release as `stable`; the built-in update prober
reads it. `unstable` points to the newest pre-release.

## Channel "protocol"


When autopilot is configred to use a channel called `some-channel`, it will request the information from following URL `<update-server-address/<channel>/index.yaml`
Essentially k0s autopilot assumes the folowing structure for update channels:

```text
<channel-name>/
    index.yaml
```

Each the channel name can contain e.g. forward slashes so you can structure the channels for example like so:

```text
stable/v1.36/
    index.yaml
unstable/v1.36/
    index.yaml
```

Each channel `index.yaml` need to provide following information:

```yaml
channel: stable
version: 1.36.5+k0s.0
downloadURLs:
- arch: amd64
  os: linux
  k0s: https://github.com/k0sproject/k0s/releases/download/v1.36.5%2Bk0s.0/k0s-v1.36.5%2Bk0s.0-amd64
  k0sSha256: deadbeef
  airgapBundle: https://github.com/k0sproject/k0s/releases/download/v1.36.5%2Bk0s.0/k0s-airgap-bundle-v1.36.5%2Bk0s.0-linux-amd64.tar
  airgapSha256: deadbeef
- arch: arm64
  os: linux
  k0s: https://github.com/k0sproject/k0s/releases/download/v1.36.5%2Bk0s.0/k0s-v1.36.5%2Bk0s.0-arm64
  k0sSha256: deadbeef
  airgapBundle: https://github.com/k0sproject/k0s/releases/download/v1.36.5%2Bk0s.0/k0s-airgap-bundle-v1.36.5%2Bk0s.0-linux-arm64.tar
  airgapSha256: deadbeef
- arch: arm
  os: linux
  k0s: https://github.com/k0sproject/k0s/releases/download/v1.36.5%2Bk0s.0/k0s-v1.36.5%2Bk0s.0-arm
  k0sSha256: deadbeef
  airgapBundle: https://github.com/k0sproject/k0s/releases/download/v1.36.5%2Bk0s.0/k0s-airgap-bundle-v1.36.5%2Bk0s.0-linux-arm.tar
  airgapSha256: deadbeef
```

So each channel can offer only single version to k0s autopilot client. In general the design pattern here is that each major.minor version will have their own channel where the latest patch release is offered.

## Automation

The channels are generated by `scripts/update_channels.py`. The workflow
`.github/workflows/update-channels.yml` runs it every six hours and on manual
dispatch, then commits the result to `main`. GitHub Pages serves the committed
files.

The script reads the k0s releases from the GitHub API. It uses the release asset
list and the release's `sha256sums.txt` for URLs and checksums, so it never
downloads a k0s binary or airgap bundle. Airgap bundle names changed in v1.36
(`k0s-airgap-bundle-<version>-linux-<arch>.tar`), so the script uses the asset
names that the release actually publishes.

To refresh the channels by hand:

```shell
GITHUB_TOKEN=$(gh auth token) python3 scripts/update_channels.py
```

The script keeps the four newest stable minors and removes the channel
directories of older minors.
